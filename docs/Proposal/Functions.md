# Functional Requirements

## 1. User Management

* The system shall allow users to register as clients or designers.
* The system shall allow users to log in and log out securely.
* The system shall allow users to reset forgotten passwords.
* The system shall verify user email addresses during registration.
* The system shall allow users to manage their profiles.
* The system shall allow users to update account settings.
* The system shall support dual-role accounts and role switching between client and designer.
* The system shall support role-based access control.

## 2. Portfolio & Designer Discovery

* The system shall allow designers to create and manage portfolio projects.
* The system shall allow designers to upload project images and project details.
* The system shall allow clients to browse designer portfolios.
* The system shall provide a discovery feed of completed interior design projects.
* The system shall allow clients to search for designers and projects.
* The system shall allow filtering by design style, room type, and budget range.
* The system shall display designer profiles and availability status.
* The system shall allow clients to save favourite designers.

## 3. Moodboards & Brief Generation

* The system shall allow clients to create and manage moodboards.
* The system shall allow clients to save design inspirations to moodboards.
* The system shall generate structured project briefs based on saved inspirations.
* The system shall allow clients to edit generated briefs before submission.

## 4. Designer Matching

* The system shall calculate fit scores between project briefs and designers.
* The system shall rank designers based on fit scores.
* The system shall display a breakdown of fit score calculations.

## 5. Project Requests & Proposals

* The system shall allow clients to create open project requests.
* The system shall allow clients to send direct project requests to specific designers.
* The system shall allow designers to view incoming requests.
* The system shall allow designers to submit project proposals.
* The system shall allow clients to compare multiple proposals.
* The system shall allow clients to accept proposals and create projects.

## 6. Project Workspace

* The system shall provide a dedicated workspace for each project.
* The system shall support project stages including Proposal, Concept, Design, Revision, and Completion.
* The system shall allow designers to upload deliverables for each stage.
* The system shall allow clients to view and download deliverables.
* The system shall maintain version history for uploaded deliverables.
* The system shall allow clients to provide feedback on stage submissions.
* The system shall allow clients to approve or reject stage submissions.
* The system shall track project progress and current stage status.
* The system shall manage project timelines and due dates.
* The system shall maintain activity history for project actions.

## 7. Communication & Notifications

* The system shall provide real-time messaging between clients and designers.
* The system shall support project-based conversations.
* The system shall indicate message read and unread status.
* The system shall provide in-app notifications.
* The system shall send email notifications for important events.

## 8. Payment Management

* The system shall integrate with Stripe for payment processing.
* The system shall support milestone-based payments.
* The system shall release milestone payments after client approval.
* The system shall maintain a payment ledger for each project.
* The system shall maintain payment history and payment status records.

## 9. Reviews & Ratings

* The system shall allow clients to submit reviews after project completion.
* The system shall allow clients to rate designers using a 1–5 star rating system.
* The system shall display reviews and ratings on designer profiles.

## 10. Trust & Safety

* The system shall support designer verification.
* The system shall allow users to report other users.
* The system shall allow users to report projects.
* The system shall allow users to block other users.
* The system shall allow administrators to review reported content and take appropriate actions.

## 11. Mobile Application

* The mobile application shall allow users to receive push notifications.
* The mobile application shall allow users to send and receive messages.
* The mobile application shall allow users to track project progress.
* The mobile application shall allow users to approve or reject project stages.
* The mobile application shall allow users to confirm milestone payments.
* The mobile application shall support role switching.

## 12. Administration

* The system shall allow administrators to manage users.
* The system shall allow administrators to manage designer verification requests.
* The system shall allow administrators to moderate reviews.
* The system shall allow administrators to manage reports and complaints.
* The system shall allow administrators to monitor projects.
* The system shall provide platform analytics and reporting.
* The system shall allow administrators to moderate portfolio content.
